## D. Genuine outstanding blockers

There is **no demonstrated remaining catalogue-wide EQL compatibility blocker**. The following operational gates block enabling scheduled detection now; they do not block preparing a controlled pilot:

1. **Effective scheduled execution is unverified.** No installed/disabled/enabled detection-rule inventory or effective Kibana configuration is evidenced. Confirm target version/feature entitlement, rule-administration/execution privileges, exact source digest, index scope, timestamp/category overrides, stable IDs, owner and schedule. Native search API-key success does not establish detection-task permissions. Set a search window covering first-to-last maxspan plus ingestion delay and schedule/gap margin; verify effective semantics. The documented five-minute schedule plus one-minute additional look-back cannot be accepted as sufficient for 10–60 minute sequences.
2. **Pilot telemetry/scope acceptance is absent.** Native compatibility is established for the recorded indices/window, not every future rollover. Assign an owner to accept per-rule stage availability, collection/retention gaps, exact WordPress paths, realtime FIM, audit/cron/systemd fields, rootcheck executable-path population and shared-agent/source-IP attribution in the selected scope. Detailed mapping settings were permission-denied; obtain an authorized snapshot or document the remaining bounded pilot risk. A mismatched path or absent required telemetry blocks claiming coverage for that rule; it need not hold back unrelated ready rules.
3. **Alert/SOC handoff is unverified.** No evidence shows EQL matches becoming usable detection alerts. Establish analyst ownership, alert context/access to source sequence evidence, severity/risk, deduplication policy, triage and feedback procedure. Confirm one bounded end-to-end alert path before relying on scheduled monitoring. Case creation is a separate optional workflow; absence of automatic Cases is not a blocker for a manual-review pilot.
4. **Operational acceptance and rollback are unspecified.** Before activation, record pilot duration/scope, review cadence, capacity/error/gap/duplicate/noise stop thresholds and an operator able to disable the pilot promptly. Preserve definition/settings and a disable/revert procedure. Without these, the deployment is not controlled.

Missing native positives for eleven rules, absence of precision/recall metrics, unresolved exotic semantics and unavailable root cluster-monitor access are not themselves blanket deployment blockers. A pilot can measure usefulness with limitations explicit. PRIV requires populated matching final usernames for the demonstrated positive path; if missing-user coverage is mandatory, that requirement blocks that use case and requires a separately versioned rule decision. MAL's unestablished real-world path population limits coverage claims, not parser readiness.
