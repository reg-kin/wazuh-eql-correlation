# Portable export configuration guidance

Read the [native configuration guide](configuration.md) first.

The [public-release package](../deployment/public-release/kibana-rules.ndjson) preserves `wazuh-alerts-4.x-*` and the original queries and schedules. Its empty `required_fields` metadata does not mean fields are optional. The [reconciliation inventory](verification/PUBLIC_RELEASE_RECONCILIATION.json) identifies each query; derive keyword predicates/joins from that exact version and use the field-capabilities procedure above, across every target index. Native `timestamp` must be a date; `type.keyword`, `agent.id.keyword`, `rule.id.keyword` and every referenced `data.*.keyword` / `syscheck.*.keyword` must have compatible searchable mappings and populated values. Native telemetry must cover SSH, sudo, audit, FIM, web, cron/systemd and rootcheck stages as applicable.

The export omits `timestamp_field`, `timestamp_override` and `event_category_override`; verify effective ordering uses `timestamp`, range filtering uses `timestamp`, and event category uses `type.keyword` in the target version. Missing configuration is an activation blocker. Stage 2A explicitly supplies these fields and remains a separate preserved proposal. Do not silently rewrite the release package to fix target configuration.

WEB-002/003/004 embed a WordPress Docker volume path under `/var/lib/docker/volumes/`; it is a deployment-specific detection predicate, retained deliberately. Review the exact full paths in the queries against the monitored estate. Ingest alert paths, pipeline configuration paths, sincedb locations, CA paths and service endpoints in this repository are deployment examples. Any local path or index adaptation requires a separate reviewed copy, regenerated integrity data and renewed qualification. No credentials, server IDs, creator identities, space IDs or execution history are required in the import package.

## Identifier classification and publication review

The [authoritative procedure](installation.md#authoritative-public-release-procedure) governs validation and import. The following classification records why retained identifiers are acceptable for experimental public source publication. Historical evidence and package bytes are preserved; no sensitive value requiring removal was identified in this review, so no sanitisation was necessary. These retained values must not be interpreted as portable deployment configuration.

If sanitisation would require altering frozen evidence or package bytes, stop and arrange a separately reviewed publication variant. |

Field adaptations also require explicit review: native `timestamp` is not interchangeable with ECS `@timestamp`, and `type.keyword` is not automatically `event.category`. Check every exact query field across all selected indices for date/keyword type, doc values, searchability, populated values, arrays, missing/null values and `ignore_above` or mapping conflicts. Verify decoder/rule IDs and required SSH/sudo/audit/FIM/web/rootcheck telemetry. Do not infer portability from empty `required_fields` metadata. Mapping or ingestion changes must be separately qualified; changing query fields, paths, joins, indices or schedule produces a different target variant with new integrity evidence.

Reference versions, local ports and schedule delay assumptions describe the lab, not a tested compatibility matrix or production timing guarantee. Package integrity does not independently attest the original archive's origin: only its recorded digest and extracted payload/manifest consistency are available here. Experimental source publication, isolated import qualification and production readiness remain separate decisions.
